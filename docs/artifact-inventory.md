# 物料库存与容量口径

inventory是只读的本地观察，不创建存储目录、不执行清理、不查询远端。它不能代替cleanup计划或正式归档验证。

```sh
python3 app_store_creative.py inventory --repo /path/to/project
```

## 对象分类

| 字段 | 含义 |
| --- | --- |
| reference_count | artifact业务记录数量；多个记录可能引用相同字节 |
| registered_identities | 已登记SHA256身份数量 |
| active_count | 活动对象路径中的实际文件数量，包括孤立或损坏文件 |
| corrupt | 活动已登记对象的大小或哈希不匹配 |
| missing | 已登记身份缺少活动文件和有效隔离副本，且无已完成永久删除记录 |
| quarantined | 活动位置不存在，但仍有大小及哈希验证通过的隔离副本 |
| purged | 有已完成永久删除记录，当前没有活动文件或有效隔离副本 |
| orphan_files | 内容寻址路径中的文件没有artifact登记；仅报告 |
| unknown_files | 对象库中的其他未知文件；仅报告 |
| unknown_quarantine_files | 隔离目录中的文件未出现在隔离操作清单；仅报告 |
| corrupt_quarantine_files | 隔离副本无法通过大小或哈希验证，不报告为可恢复 |
| unsafe_links | 对象库符号链接；不读取目标 |

工作文件继续分别报告registered_files、changed_files和unregistered_files。不根据文件名或相同字节猜测归属。工作根本身或子目录的符号链接不跟随；生产在登记尝试前也拒绝符号链接工作位置。

## 读取失败与未观察状态

不存在的目录与无法读取的目录分开报告：确认不存在的目录可以返回零；目录遍历或文件身份读取失败时，该区域数量及容量为null。observation_errors逐项提供area、path及reason，其他可读取区域继续返回其观察结果，不将部分扫描伪装成完整库存。

对象库无法读取时，active_count及媒体容量为null，已登记身份列入unobserved_registered。此时不根据未观察到文件报告missing，也不把隔离或永久删除数组为空解释为数量为零。Studio显示未观察状态、读取区域和原因；修复后重新检查才能得到当前数量。

生命周期records是引用及操作的权威来源。该树读取失败或含不安全链接时，整个库存请求失败；不能只读取部分记录再声明引用完整。清理计划及执行需要完整引用树和对象观察，迁移快照需要所有相关存储区域完整观察；缺口在新维护记录或目标复制创建前拒绝。已有计划仍须在执行时复查，不能凭历史库存绕过。

这不提供全目录并发事务或全部父路径竞态防护。当前专项测试和HTTP演练注入目录遍历与文件lstat错误；另有真实临时对象目录chmod撤销读取权限的两项验收，确认未知库存、拒绝清理/搬迁计划及恢复后物料完整。此证据只覆盖对象读取权限，不代替其余权限、路径替换或跨文件系统中断验收。

## 容量口径

active_object_bytes和quarantine_file_bytes按实际本地文件的逻辑大小统计，同一SHA的多个业务引用不重复增加活动对象大小。payload_logical_bytes合计活动对象文件和隔离文件的逻辑大小。

payload_unique_inodes按设备与inode去重，可识别活动对象与隔离副本之间的硬链接。payload_allocated_bytes_estimate按唯一inode的stat块数估算分配空间；APFS共享extent、克隆及压缩没有进一步解析，因此不是精确的已释放磁盘空间。永久删除报告的bytes_removed同样是被移除隔离文件的逻辑字节，不是整个项目的磁盘回收量。

work_file_bytes、release_directory_bytes和publication_directory_bytes分别统计这些本地目录的普通文件大小，不表示其中每个文件都已通过来源或正式包验证。other_object_file_bytes报告对象库其他未知文件大小。符号链接目标不计入。

Git历史、LFS远端和external后端容量未测量时返回null，不写成零。删除工作树或本地隔离文件不会证明Git历史或LFS远端容量减少。

## 并发与后续维护

库存是观察结果，不提供全目录事务快照。并发生产或清理期间文件可能变化；遇到读取失败应重新观察，不能用库存输出绕过执行前的引用及哈希校验。

孤立对象不能自动判定为可回收，可能来自尚未登记的生产或被中断的操作。当前仅报告，后续需通过执行记录和授权的孤立对象处置流程确定归属。工作文件及日志的隔离/清理和完整后端容量采集仍待实现。迁移副本的保留、隔离、恢复及永久删除已提供独立用例；完整历史位置投影和真实故障验收仍未完成。目录迁移及多次往返已接入，见 [目录迁移](storage-relocation.md)。


## 迁移保留副本

统一库存新增 relocation_backups；CLI 和 Studio 的 GET /api/inventory 使用相同内核。HTTP 接口仅使用项目配置，不接受任意目录查询参数。当前范围包括已激活正向迁移的源副本（kind 为 forward-source），以及反向迁移在 preserved_backups 中保留的副本（kind 为 reverse-backup）；未完成操作的暂存及待恢复目录单独列入 staging，见下文。

核验先读取计划、准备日志、切换意图及回执，检查其哈希、项目/配置范围、布局和原根目录身份；证据不一致的操作进入 unverified_operations，不按被篡改的路径扫描。副本本身按设备/inode和完整文件清单核验，报告额外、缺失、变更文件及不安全链接；额外文件保持原样。正向计划记录源根目录身份，切换前采集完整源树清单并将其哈希绑定到切换回执；准备和切换前复查源根身份，相同字节的目录替换也拒绝。计划或准备时尚未存在的源根不虚构为保留副本。

| status | 含义 |
| --- | --- |
| VERIFIED | 目录身份及完整文件清单的大小/哈希匹配 |
| CHANGED | 存在额外、缺失、变更文件或内部不安全链接 |
| MISSING | 保留副本位置当前不存在 |
| IDENTITY_CONFLICT | 同名位置已被不同目录或其他文件替换，即使字节相同也不通过 |
| UNSAFE | 副本根或其路径包含别名、符号链接，不跟随目标 |
| ACTIVE_CONFLICT | 副本位置与当前配置的存储范围重叠（含待激活目标），不当作可维护备份扫描 |

copies 中 observed_logical_bytes 在未观察时为 null；expected_logical_bytes 仅来自登记清单。capacity.observed_logical_bytes 合计 copies 和 staging 的实际读取部分，unobserved_copy_count 和 unverified_operation_count 同时显示观察缺口，不能将合计当作所有副本的总占用。备份容量独立于当前对象库容量，避免混淆活动媒体与重复副本。unique_file_inodes 和 allocated_bytes_estimate 同样只是本地文件去重及块数估算。

目录读取失败进入未验证操作，不静默当作空目录成功。库存不删除副本，不产生清理批准；VERIFIED 也不表示副本可以回收。备份保留策略、引用保护、隔离、恢复及永久删除需要独立实施和验收，不能把整个用户目录交给删除命令。


正向源副本核验保留原完整树清单，包括旧运行记录及操作证据；本次切换随后新增的意图、封锁、完成回执及恢复记录，只有与当前权威操作记录的大小/哈希一致时才单独列入 verified_added_controls，不把整个操作目录忽略。其他额外文件继续报告。续执行与回滚使用同一清单绑定校验；篡改清单、根位置或操作范围时拒绝激活及恢复覆盖。无法读取源树时在切换封锁前拒绝，不登记为空树。

多次返回后，同名旧根可能已成为活动位置或不同目录身份；此时不会按 VERIFIED 源副本报告。ACTIVE_CONFLICT 和 IDENTITY_CONFLICT 是保留现场、检查后续操作记录的提示，不授权清理当前位置。副本容量按物理源根分组，工作区包含对象库时不重复扫描嵌套根。


## 暂存与待恢复目录

relocation_backups.staging 按准备意图和计划布局登记未完成操作。创建归属标记后、复制物料前，内核为每个实际创建的根保存目录设备/inode证明；准备完成时，staging_root_proof_sha256 将各证明的规范化内容哈希绑定到不可变 PREPARED 回执。准备复查、切换、正向续执行、反向恢复/回滚及库存都核对该绑定；同字节目录替换或单独改写身份证明也拒绝。没有目录身份证据或归属标记被修改时报告 UNVERIFIED_OWNERSHIP，不据此扫描或授权删除。

每项同时返回 phase 与内容 status。phase 区分 PREPARING、PREPARED、PREPARATION_FAILED、SWITCH_INTERRUPTED、ROLLED_BACK、CANCELLED 和 CANCELLED_PARTIAL；VERIFIED 只说明该目录的准备清单字节匹配，不表示操作已激活或可以清理。只有缺失计划文件、没有其他差异时为 PARTIAL；额外、变更或不安全文件为 CHANGED。取消后已移除的位置可以显示 MISSING，结合取消回执理解，不推断目录内容仍在原处。

发布或交换后，核对原准备证明及交换日志，按实际位置报告 kind 为 pending-target 的新副本；反向交换保留的旧副本可列为 pending-backup。未发布根仍为 staging。不通过目录名或配置变化猜测是否已完成。待恢复目标可能包含切换时追加的操作记录，超出准备清单的文件继续列明，不能因此忽略未知文件或执行整目录删除。

这仍是只读观察。phase 为 SWITCH_INTERRUPTED 时使用专门恢复/回滚入口；不得把取消暂存接口用于已开始切换的目录。容量统计包括读取到的暂存数据，未观察的位置和未验证操作继续明确报告缺口；完整目录并发快照、保留、隔离和回收策略尚待实施。

## 迁移副本保留计划

`cleanup plan-relocation-retention --retention-days <days>` 生成不可变维护计划，要求显式给出非负整数期限，不自动采用候选对象的保留策略。期限从切换完成回执的时间计算。

计划只从完整核验通过的正向源副本及反向备份中选择已登记、位置匹配的内容寻址对象。每项记录源路径、目录身份、大小、哈希、决策和理由；候选还绑定当前活动对象的路径及文件身份，并核验独立副本的大小和哈希。同 inode 的硬链接不作为独立恢复证据。工作文件、元数据、所有权及恢复证据继续保留；仅有相同哈希不能使工作文件成为清理候选。

未到期限、配置仍引用原文件、独立恢复副本缺失或损坏均保护该文件。目录身份或内容异常整体排除；存在待恢复暂存或未核验操作时，暂不选择任何副本对象。计划保留暂存和异常清单，未知文件不会被删除。本接口仅完成规划，不执行隔离或删除。副本准备、提交、恢复及永久删除使用下方独立命令并即时重验，现有试制对象清理命令不能执行此计划。


`cleanup verify-relocation-retention --id <plan-id>` 使用同一内核状态计算进行复查。除路径、目录身份、大小和哈希外，计划也绑定副本文件与独立恢复对象的inode，以及当前配置和全部非维护生命周期记录的内容快照。同字节文件替换、新运行、配置引用变化、未知文件新增或恢复副本变化均使旧计划失效；新生成的维护计划本身不会造成引用快照失效。复查返回READY及候选数量/字节数，但不写新维护记录，也不执行隔离。其他类型的清理计划不能传入此接口。实际隔离执行仍需在锁内调用该门禁并处理执行中断，独立调用复查不构成未来执行许可。


## 隔离准备库存

统一inventory新增quarantine_preparations，CLI与Studio的/api/inventory均返回相同内容。operations中的phase区分PREPARING、INTERRUPTED、PREPARED、COMMIT_STARTED、QUARANTINED、RESTORING及RESTORED；status反映当前实际内容，不由阶段直接推导成功：VERIFIED、PARTIAL、CHANGED、MISSING、IDENTITY_CONFLICT、UNSAFE或UNVERIFIED_OWNERSHIP。

扫描前验证操作与原计划哈希、配置/存储权威、派生目录、目录身份、逐文件创建记录和准备回执。回执绑定文件身份；已准备媒体损坏、同字节文件替换、回执或创建证明变化均不能继续显示有效。身份冲突或符号链接根不扫描；目录读取失败和证据异常进入unverified_operations。未知文件、缺失文件、内容变化、身份冲突及链接分别报告，全部保留。

容量包含实际安全扫描到的逻辑字节以及按inode去重的stat块数估计，不是全存储后端的物理占用；未扫描操作的observed_logical_bytes保持null并报告未观察/未验证数量。该库存覆盖受管理隔离操作；source_removal_executed在已提交时为true、准备或恢复完成时为false、部分提交或恢复中为null。库存有效不代表批准移除源副本。隔离提交和恢复已接入；Studio库存界面、源处置库存统一及永久删除尚待完成。


### 源隔离处置视图

relocation_backups对含已核验隔离文件且没有其他异常的根返回QUARANTINED。quarantined_files逐项绑定操作ID、原相对路径、隔离路径、哈希和大小。位置映射先验证原计划、准备媒体、创建证明、提交/恢复意图和回执，再核验源根/父目录身份、隔离原文件inode及内容；不能仅凭保留文件名消除缺失/未知条目。容量仍统计实际字节，不因位置变化减少。

原始迁移清单保持不可变。库存只将确切受管理移动映射为位置视图：部分提交也可报告已有隔离文件，完成程度由隔离操作phase单独表示；恢复后根回到VERIFIED。未知备注、损坏、替换身份或错误回执仍报告CHANGED或disposition_errors，不隐去异常；有处置错误时保留计划保护其他副本对象，同一隔离根不会再次进入清理候选。CLI及Studio HTTP使用相同结果。该视图不使尚未恢复的根可直接用于反向迁移，也不授权purge。


### 永久删除观察

隔离库存按原计划、删除意图、逐文件检查点及完成回执区分PURGING/PURGED。观察核验受保护根的完整文件与身份集合，接受原位置、已登记捕获位置或有确切检查点的删除缺失；没有检查点的丢失及任何未知文件仍为异常。PURGED准备区容量可观察为0；不把未读目录写成0。

源根返回purged_files及PURGED，混合仍隔离文件时返回PARTIALLY_PURGED；这些状态描述已登记媒体处置，不意味着整棵目录已删除。原清单、元数据及当前对象保留，根容量按实际剩余字节报告。删除完成后重新出现的数据被保留并报告异常，不会由重试再次删除。


## 迁移后的历史隔离库存

迁移准备回执登记每个受管理隔离根的相对位置、目录身份及实际文件身份/大小/哈希，切换意图继续绑定完整准备回执。库存通过当前激活回执核验配置、项目、计划、准备及切换证据，再检查当前位置；不改写原始隔离操作、来源或取消/恢复/删除回执。反向返回相同路径也使用新副本证明，路径相等不能证明inode相同。

取消和恢复后的副本仍报告原终态以及当前实际内容状态。同字节替换为IDENTITY_CONFLICT；未知文件为CHANGED并保留。已永久删除的副本报告PURGED及空目录实际占用；依据原计划、逐文件删除检查点及终态回执证明删除，不要求被交换的旧目录继续具有原inode。该终态观察不授权再次删除，也不放宽执行器存储绑定。

上述针对已完成迁移的隔离准备区视图。完整保留副本位置投影及全部父路径竞态仍需进一步验收；迁移中断续执行和反向回滚已检查日志定位的隔离副本及旧备份身份，真实断电仍待验收；不能将库存观察作为清理计划或权限。


## Studio 库存入口

项目已加载后，在Asset inventory中点击Check storage读取保存配置下的统一库存；与CLI inventory及GET /api/inventory共用生命周期内核。该入口显示物料登记数量、本地媒体/隔离/工作文件/归档/发布记录占用，以及迁移保留副本、暂存和隔离准备。逐项展示维护阶段与实际内容核验结果，取消状态不能掩盖损坏或未知文件。

未知容量显示Not measured，不当作0 B；保留副本占用独立列出，不将可能共享磁盘块的值相加宣称可释放空间。物料异常与未核验操作可以展开查看具体路径和原因。检查时间仅表示本次响应完成，后续生产或维护后需再次检查。未保存编辑不改变库存检查的保存配置范围。

初次加载不显示完成或健康结论；检查开始时清除旧结果，失败后保留错误及重试入口，不能继续展示旧检查时间作为当前结果。不完整响应拒绝展示，超时明确指出库存检查。该页面当前为只读；维护的计划、审批、执行和恢复继续使用已有独立用例，完整Studio维护操作视图仍待实现。


## 归档载荷预算

`storage media-budget --repo /path/to/project`观察已登记、完整验证的本机封存修订；`--candidate-id`估算再封存一次的新增载荷。与inventory的目录容量口径不同，这里按每个修订的实际物化产物路径计数，包括媒体、输入和渲染证据，排除元数据。已有候选再次封存仍是新增一份修订，不减去旧副本。

完整本机观察后按项目artifactPolicy.mediaBudgetBytes返回NOT_CONFIGURED、WITHIN_BUDGET或OVER_BUDGET；无法验证任何归档时返回UNKNOWN，current_payload_bytes与forecast_payload_bytes为null，observed_payload_bytes只代表已验证部分。Git历史和远端使用量始终为null。报告不修改配置、不自动清理、不阻止封存，也不证明远端成本。Studio通过同一只读接口展示这些区别。
