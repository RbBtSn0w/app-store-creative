# PPO Agent 实施与验收计划

**状态**　已实现 P0 离线路径；真实 ASC 回放仍需一份可核对的历史观测和实测素材。范围与数据契约见[技术设计](../prd/ppo-agent-experiment-design.md)。以下按可独立审查的改动拆分，可直接转为 Project 中的 Issue。阶段顺序表达依赖，完成状态以后以对应 Issue、PR 和 CI 回执为准。

## 可运行的交付

CLI 已提供 policy 预检、cardOrder、绑定封存交付与远端 ID 的 `ppo bind`、验证快照的 `ppo assess` 以及 `result --assessment`。复产使用限定范围的独立项目，并在候选创建前比较每张截图的 SHA-256。现有人工 result 和显式 variant 保留。操作入口与可填写的 JSON 见[运行说明](../../plugins/app-store-creative/skills/app-store-creative/references/ppo-assessment.md)。

离线集成测试使用合成 App Analytics 数据、真实生命周期封存的 PNG 与受控渲染器，覆盖从 CLI 交接、绑定、判读、持久化到生产回执及渲染不一致失败。T17 仍需真实实验来源。自动采集和 Studio 的 F 阶段按下表单独排期。

本地验证记录（2026-11-23）：PPO 测试 35/35、既有 release review 测试 5/5、插件打包冒烟通过。开发期间的全量发现运行 1331 项，66 个错误来自本机监听端口权限，34 项跳过；另有 1 个 Swift 编译缓存权限失败，指定可写缓存目录后单项复跑通过。生产生命周期的端口错误在未修改的 HEAD 上可复现。完整 macOS CI 和真实 App Analytics 对照仍待验收。

## 交付顺序

| 包 | 优先级 / 依赖 | 改动及负责人角色 | 合入条件 |
|---|---|---|---|
| A. 固定基线与样本 | P0 / 无 | 维护者确认未提交的 result/reproduce 依赖已合入或纳入同一交付；采集一个脱敏真实历史实验，记录其页面范围、名称到 ID 的映射、原始截图及能验证的素材清单。同时准备合成回放 | 现有 CLI 回归通过；注明每份数据来源及无法恢复的字段。没有真实样本可继续开发，保留“真实验收待完成” |
| B. 事前计划与换序 | P0 / A 的代码基线 | CLI 与素材引擎增加可选 policy、cardOrder、预检和范围；保存原始策略；修正 iOS handoff 创建上下文与设备参数 | 合法换序只改变顺序；估时和分流提示正确；离线草案和历史配置仍可用 |
| C. 绑定与结果采集 | P0 / A；与 B 的配置开发可并行 | 定义 binding/snapshot 模板、标准化读取、远端 ID 与交付映射、原始证据摘要校验；通过 B 的真实交付清单集成 | 同名不同 ID、改基线、篡改文件均有诊断；缺 ID 可以形成草案，不能进入可决策记录 |
| D. 判读与决策 | P0 / B、C | 增加 assess 纯函数、CLI、机器输出及人工说明，接入 result；实现终局及无结论路径 | 下方所有决策分支有固定输入与期望，重放完全一致；并发或重试不能改写首次记录 |
| E. 复产与 Agent 指引 | P0 / D | 在现有 reproduce/produce 中贯通实测范围与素材摘要；提供“选题→采集→判读→复产预览”的操作范例 | 同一快照通过正常 CLI 到达正确交付和范围；无结论的案例不产生获选交付；提供一次真实历史回放报告 |
| F. 自动采集与 Studio | P1 / E；单独排期 | 接口适配先比较同一实验的 UI 与 API，再决定自动采集字段；Studio 如实施则只消费相同契约，显示基线、证据和决策原因 | 逐字段一致性有记录；Studio 通过 Vitest、TypeScript、build；跟踪的 dist 同步 |

**首版完成点**为 A–E 的 P0 验收。C 可先用合成输入实现；真实实验缺少历史素材或事前策略时，回放应如实返回待核对或无结论。可用一个有完整策略与素材的受控试点补齐“真实获选→复产”验证。F 的进度独立。首版不要求在线启动、停止或应用实验。

## 测试场景与判定

所有数据除特别注明均为合成。单元测试用 unittest.TestCase，文件读写用 TemporaryDirectory；CLI 集成通过实际入口、临时项目及离线素材执行。真实账户凭据只用于单独验收。

| 编号 / 层级 | 操作或输入 | 可观察的期望 |
|---|---|---|
| T01 配置 | 旧配置无 policy；父、子命令两种位置传 --repo；从其他目录调用 | 旧输出契约可用，所有输入输出均定位到同一项目 |
| T02 计划 | 2 组共 40% 分流；另测 0、101、true、4 组及 100% 分流 | 合法组各 20%、原版 60%；非法输入拒绝；同期原版零分流有明确提示 |
| T03 计划 | ASC 时长估算分别为 90、91 天、未知；另一个实验运行中 | 分别得到可行、延后、需补资料；已有实验时维持候选 |
| T04 素材 | B 交换两张首图；重复、漏项、未知 ID、其他素材字节变化 | 有效排列保持卡片身份与内容；无效排列拒绝，意外变化指出 locale、设备和文件 |
| T05 交接 | iOS 创建上下文已知及缺失；一个市场有两种设备；缺 delivery、模板占位符 | 命令参数匹配本机 asc help，设备分别对应正确目录；缺信息仍可预览草案但不能绑定为已部署 |
| T06 来源 | 交换远端组 ID、重名、不同 App、重复 original、缺组、源文件变动、比较基线切换 | 无法核实时不产生终局决定；诊断指出字段。展示别名变更但 ID 未变仍可读 |
| T07 数值 | null、0 曝光、负曝光、布尔数、NaN、置信度 101%、低于 0 的合法 lift、无时区日期 | 空值保留或等待，非法数值/日期拒绝；下降保留负号 |
| T08 判读 | 结束，原版 CVR 20%，B 为 21.2%，Apple lift +6%、confidence 93%、Performing Better，预设门槛 +5% | use-treatment 选择 B；解释使用 +6% 相对提升，报告原始值与证据 |
| T09 边界 | 结束，门槛 +5%、实际 +5%、confidence 90%；另测 89.9% 却标 Better、或 lift 符号与状态冲突 | 边界允许；矛盾输入进入 needs-review，不以四舍五入晋级 |
| T10 等待 | 同 T08 但实验运行中；Collecting Data；Likely to be Inconclusive | wait，展示候选或低把握原因，不生成终局 result |
| T11 保留 | 已结束，全部明确 Worse；另测全组有明确证据但正提升仅 +3%，门槛 +5% | keep-control，能区分效果变差与商业门槛未达 |
| T12 无结论 | 已结束且仍在收集、指标不可见、缺事前门槛；B 达标但 C 未决 | inconclusive，报告证据缺口；不能触发获选复产 |
| T13 多组 | B、C 均优于原版并达标；另测 B 达标、C 明确较差 | 前者 needs-review；后者选 B，组间比较依据清晰 |
| T14 时序与持久化 | 同快照重复导入；两进程写同目标；写一半中断；旧快照晚到 | 相同内容幂等、冲突可见、无半写结果；旧快照能独立重放，不能覆盖最新决策 |
| T15 兼容与完整性 | 旧 result、显式 --variant、新 assessment；改动继承的主题、变体定义或源截图；旧无摘要 handoff | 原有路径兼容；新版识别漂移或明确报告证据缺失；记录的选中交付可追溯 |
| T16 CLI E2E | 项目有两种语言两种设备，实验只测 en-US/iPhone。正常 CLI 完成 handoff→assess→result→reproduce；另跑明确较差与无结论 | 采用时 dry-run 零写入且只列一组；执行后核对实际回执、资产顺序与摘要；其余决定不生成获选交付 |
| T17 真实回放 | 维护者用同一真实历史快照和原始素材独立核对，再运行 Agent | App、实验、基线、变体、读数、范围逐项一致；差异与不可验证项逐项记录。合成数据永远标记为 fixture |

## 验证方式

开发阶段使用 Python 3.11 或更高版本。当前 macOS 工作区用 Homebrew Python 运行以下基线，PPO 25 项通过、release review 5 项通过（2026-11-23）。这 30 项用于守住现有行为。新增离线回放见 test_ppo_assessment.py；T17 需要单独的真实样本。

```sh
python3 -m unittest discover -s tests -p 'test_ppo_experiment.py'
python3 -m unittest discover -s tests -p 'test_release_review.py'
```

新增评估模块使用独立 test_ppo_assessment.py。提交前运行相关模块和真实 CLI 离线回放；合入由 macos-15 / Python 3.12 的四个 CI 分片和合并测试报告判定。命令如下，N 取仓库矩阵值。

```sh
python3 .github/run_sharded_tests.py --shard "$N" --total 4 --report "test-reports/shard-$N.json"
```

真实回放报告应提供脱敏来源、采集时间、原始显示精度、实测范围、输入摘要、规则版本、建议及其理由、操作者独立判读、复产预览和不一致项。若判读或材料映射不一致，定位到 C、D 或 E 修复后重放同一输入。真实回放通过前仅标记离线验证完成。
