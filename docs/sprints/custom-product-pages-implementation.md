# 自定产品页面实施计划与验收

已实现本地规划、Studio 对照与排序、受管发布目标、操作恢复及详细报表导入。真实账号试点待执行。范围、术语和 CLI 定义见[技术方案](../prd/custom-product-pages-design.md)。下列工作包可直接拆成 Issue；工期以验收证据推进，Apple 审核和数据积累单独记录。

## 当前可运行的入口

- 主 CLI 的 `cpp discover` 通过分页 ASC 读取页面、版本和本地化。`cpp plan` 复核 agent 提案与本地证据。`cpp preview` 与 Studio 共用对照页面，Studio 支持按设备和语言调整素材顺序。
- `cpp handoff` 接受观察快照，输出逐项差异。`cpp claim` 和 `cpp reconcile` 保存和核对外部操作意图。已绑定的媒体目标可传给现有受管 publication 流程，经封存、授权后导出。审核交给操作者。
- `cpp status` 展示最后观察的版本与 URL。`cpp report` 从 Apple 详细日报生成页面切片。试点的真实 ASC 回执、可见链接、真机深层链接结果及实际报表须另行取得。
- [输入样例、执行与恢复](../../plugins/app-store-creative/skills/app-store-creative/references/custom-product-pages.md) · [可回放的测试](../../tests/test_cpp_campaign.py)

## 交付顺序

| 工作包 | 前置 | 改动与负责人角色 | 完成证据 |
|---|---|---|---|
| A · 接口取证 | 无 | ASC 集成维护者收集脱敏的 CPP 页面、版本、本地化、图集、视频集和审核状态样例，核对当前 asc help。分析维护者登记报表类型、列、粒度和单位。没有真实样本的合同注明 provisional | 样例来源及版本、能力表、可重播夹具；不支持的响应有失败用例 |
| B · 核心与 agent | A 的读取合同 | Runtime 维护者实现 brief/proposal/plan schema、CPP CLI、库存匹配、证据校验与命令路由。Skill 提供 brief→候选→决策样例 | CLI 从不同 cwd 可重放，四种决策和 needsEvidence 均有判例，plan 无磁盘或远端副作用 |
| C · 创意预览 | B | Studio/渲染维护者接入同一计划，在活动工作区生成可验证的媒体；增加按语言、设备对照与修改后的 revision 检查 | 试点场景有可读首图、顺序差异和补拍提示；同一输入重复导出产物可追溯；Studio 三项验证通过 |
| D · 发布及恢复 | A、B；端到端依赖 C | Publisher 维护者实现两阶段目标绑定、精确计划、CPP 专用观察及恢复；审核交接、状态与获批链接读回 | 旧交付可重验；跨资源误传被拦截；故障注入重跑无重复创建；待审和可分发状态可区分 |
| E · 分析导入 | A、B；可与 C/D 并进 | Analytics 维护者实现详细报表映射、去重、修订、覆盖解释及报告；输出可复查的切片数据 | 同文件重导结果一致；缺失/歧义可解释；分子分母和维度可核对 |
| F · Levelory 试点 | C、D、E | 产品负责人选定已发布且有证据的功能、教程渠道、语言和规格。执行离线演练，再按已有授权流程操作真实页面 | 留存教程简报、默认页对照、执行回执、获批可见 URL、页面与商店核验、首份实际数据或截至某日的数据待到说明 |

建议先合并 A+B 的只读 CLI，拿真实教程试用；C 与 D 可分别合并后集成。E 在首条渠道链接上线前做完导入回放即可。提交时单独标识「离线验证」「真实草稿」「已送审」「已可访问」「已有可分析数据」。遇到线上异常时可暂停该活动的 Publisher 执行，保留最终已知远端状态、继续本地预览与诊断。

## 测试矩阵

夹具把 brief、默认页、已发布/草稿 CPP、截图/视频清单、ASC 响应和报告分段放在同一虚构 app 下。另备同名页面的第二个 app 和一个历史默认页 publication plan。以下是待实现的验收用例。

| ID | 层级及场景 | 输入/操作 | 可判定的预期结果 |
|---|---|---|---|
| T01 | CLI 兼容 | 缺少 CPP 配置的旧项目；--repo 放在子命令前后；从非项目目录启动 | 两种位置指向同一项目；历史 PPO 与默认页命令结果保持一致 |
| T02 | Schema | 空语言、重复槽位、非法平台、bool 冒充整数、越界路径或符号链接 | 定位具体字段和原因；没有写盘或调用执行器 |
| T03 | Agent 决策回放 | 默认页已满足、现有 CPP 匹配、同受众需更新、新场景需专属 URL 各一组 | 分别输出 reuseDefault/reusePage/updatePage/createPage；理由引用画面和渠道依据 |
| T04 | Agent 证据 | 提案用「向外分享」证明「导入」，或引用开发分支功能、缺失截图、竞品文案要求发布 | 标出具体缺口并停止交付；评测按证据和动作打分，容许文案表述不同 |
| T05 | 库存与策略 | 清单未翻页完成、同名候选、70 页时新建、70 页时更新已有页 | 前三种分别要求补快照、消歧、处理配额；最后一种允许继续 |
| T06 | 本地化 | 两语言两设备，遗漏一张、关键词不在该语言获批集合、深层链接无路由证据 | 准确标出受影响槽位；允许修正或明确移除可选项，其他语言保持原样 |
| T07 | 渲染 | 只换首图、重排、显式移除、继承及视频封面各一组 | 对照和清单逐项相符；PNG 实际像素与目标一致，视频与封面来自同一交付；默认页素材不被覆盖 |
| T08 | Studio | 键盘切换设备/重排，两个窗口交叉编辑，A 的旧请求晚于 B 的新请求返回 | 可读顺序和预览一致；陈旧结果丢弃，旧 revision 保存返回冲突 |
| T09 | 目标隔离 | 交换两个 app/page/version/locale 的任一 ID，或把 App 版本 ID 填成 CPP 版本 | 写前失败、远端写调用为零；旧计划使用原哈希仍能导出和验证 |
| T10 | 新建/模板 | create 返回初始版本与主语言；另需增加第二语言 | 读回已有资源，只新增缺少的语言；第二次运行返回同一 pageId |
| T11 | 精确授权 | 批准后换图、改字、调序、新增删除操作或改变远端集合 | 摘要或远端前置条件失效，展示新差异，旧授权不能执行 |
| T12 | 恢复/并发 | 创建已成功但响应丢失；两个执行者竞争；同名候选无法确定归属 | 唯一证据可补回执；同租约只有一个写者；未能消歧时不自动重试创建 |
| T13 | 部分上传 | 第二语言视频失败；第一次截图已上传；429 后成功、403、审核 409 | 已匹配截图跳过；按响应退避或报告权限/审核锁定；每一步保留独立结果 |
| T14 | 观察完整性 | 视频仍处理中，或已处理但不可播放、封面读取失败；回执跨页面或哈希错误 | 分别呈现问题且不标为媒体就绪；错误范围或篡改回执不能注册 |
| T15 | 审核/分发 | 首次上架、已有获批版本、被拒、批准但隐藏、旧版本可见且新版审核中 | 给出对应审核交接；只标记实际核验过的可见版本与 URL；不误发布 App 版本 |
| T16 | 设备 | 已核验支持的 18+ 设备打开深层链接；旧系统打开同一页面 | 新系统到约定入口；旧系统完成常规打开。保存设备、系统版本和实际结果 |
| T17 | 分析幂等 | 同一报表重导、修订文件、日周重叠、同名页面曾改名、含额外未知列 | 重导不增量叠加；修订覆盖；维度不会重复相加；歧义隔离；缺必需列报告格式错误 |
| T18 | 指标解释 | 隐私缺行、明确零、零分母、不同来源对照、缺去重访客、无首次保存事件 | 保留零与未知；无效转化率为空；输出有范围的描述，无虚构提升、归因或激活数 |
| T19 | 离线 E2E | 从 CLI 输入教程 brief，经 Studio 预览，假 ASC 完成创建、部分失败恢复、审核观察、报表导入 | 页面绑定、顺序、文案、语言、远端 URL、报表页一致；第二次运行远端增量写次数为零 |
| T20 | 真实试点 | 真实发布版本素材、授权草稿、人工提审、商店链接及首份详细报表 | 发布证据逐项可回溯；未达到显示门槛时保留待观察状态，采用实际报告后才验收分析 |

## 执行与放行

- Python 使用 unittest.TestCase 和 tempfile.TemporaryDirectory()；用可记录参数和调用顺序的 fake asc 替代网络。对每一步远端写入注入「服务端成功，客户端未收到响应」，重启新进程恢复。保留有序调用日志和最终资源数作为断言。
- Agent 回放由无网络 fixture 驱动，断言 decision、引用 ID、缺口与禁止的写操作。另用真实宿主 agent 跑相同 brief，人工复核首图是否能证明教程承诺，记录模型/版本和错误案例。确定性合同检查与生成质量分别报告。
- CLI 集成使用真实入口和临时产品仓库；先执行 CPP 定向用例，再运行 python3 -m unittest discover -s tests -p 'test_*.py'。CI 继续使用 macos-15 四分片、300 秒 watchdog 和汇总报告。
- Studio 改动在 staging 前依次执行 npm test、npx tsc --noEmit、npm run build；检查 runtime/studio/dist 与源码同步。在生产构建完成桌面宽度和窄窗口、纯键盘对照检查。
- 真实 ASC 凭证不进入 CI。真实样例脱敏后保留字段形状与父子关系，mock 结果只计入离线验收。真实试点没有既有可见页面时，需要等待审核并读回后才能宣告 URL 可分发。
- 业务验收记录从简报到可审阅页面所需时间、人工改了哪些素材与文案、是否重复建页，以及教程链接能否打开预期页面。首轮作基线，后续再设效率目标；评估获客效果时保留渠道、时窗及覆盖说明。
