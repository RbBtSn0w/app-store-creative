# ADR-001: Proportional Layout Scaling and Multi-Platform App Preview Video Architecture

**Status:** Accepted
**Date:** 2026-10-02
**Deciders:** rbbtsn0w, Antigravity Agent

## Context
In App Store Creative Studio v2.0/v2.1:
1. **Issue #6**: Headless Chrome 1:1 physical pixel export uses target display resolutions (e.g., iPhone 1320x2868, Mac 2880x1800), while card internal styling (typography, paddings, device chassis) was rendered in fixed CSS pixels calibrated for a 400px wide interactive preview. This caused cards in high-resolution targets (such as Mac 2880x1800 or iPhone 1320x2868) to be tiny with massive empty borders.
2. **Issue #7**: Video generation engine (`video_engine.py`) hardcoded iPhone portrait/landscape aspect ratios (886x1920 / 1920x886) and ignored user-configured `width` / `height` overrides. When generating App Previews for Mac targets, App Store Connect strictly rejects 1920x886 because it requires 16:9 (1920x1080) or desktop 16:10 resolutions.

## Decision
1. **Resolution-Agnostic Viewport-Relative Scaling in Export Mode**:
   - In `CardView.tsx`, when `isExport` is active, calculate the base virtual design canvas size according to the target type:
     - Mac targets (`mac_*`): base design canvas is 720×450 (16:10 aspect ratio), with Mac frame mockup calibrated to fill ~60-70% of canvas width.
     - Tablet targets (`ipad_*`, `google_play_tablet_*`): base design canvas width is 480px.
     - Feature graphics (`google_play_feature_graphic`): base design canvas is 600×293px.
     - Phone targets (`iphone_*`, `google_play_phone`, etc.): base design canvas width is 400px.
   - The export container scales using CSS transform `scale(scaleFactor)` with `transform-origin: center center`, where `scaleFactor = targetPhysicalWidth / baseVirtualWidth`.
   - The outer container dimensions exactly match `targetPhysicalWidth` and `targetPhysicalHeight`, and the inner scaled canvas is centered, providing pixel-perfect 1:1 rendering at any store physical resolution without blurry interpolation or layout drift.

2. **Config-Driven App Preview Video Resolution & Mac Target Awareness**:
   - In `video_engine.py`:
     - Allow explicit user overrides for `width` and `height` from `previewVideo` configuration block in `creative.config.json`.
     - Detect Mac targets (`mac_*`) or general desktop orientation to default landscape videos to 1920×1080 (16:9 Mac App Store standard) instead of mobile 19.5:9 (1920×886).
     - Maintain backward compatibility for mobile targets defaulting to 886×1920 (portrait) and 1920×886 (landscape).
   - In `creative.config.schema.json` and `types.ts`, officially declare optional `width` and `height` properties in `previewVideo`.

## Options Considered

### Issue #6 Layout Scaling

#### Option A: Transform Scale Container with Device-Specific Virtual Base Dimensions (Selected)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Low |
| Visual Fidelity | High — preserves exact typography, shadow, bezel radius proportions |
| Scalability | High — supports arbitrary targets without rewriting CSS units to vw/cqw |
| Performance | Instant CSS hardware-accelerated transform in headless Chrome |

**Pros:**
- Keeps the exact preview design geometry and styling identical between Studio preview and exported PNG.
- Completely avoids fractional CSS pixel rounding bugs and media query explosion.

**Cons:**
- Requires clean overflow and centering on the export wrapper.

#### Option B: Dynamic rem / Tailwind container queries across all components
| Dimension | Assessment |
|-----------|------------|
| Complexity | High |
| Visual Fidelity | Medium — risk of font metric mismatches and wrapping deviations |
| Scalability | Low — every new device frame component must adopt dynamic units |

**Cons:**
- High refactoring cost, high regression risk for existing components.

---

### Issue #7 App Preview Resolution

#### Option A: Config Overrides with Automatic Mac / Desktop Target Detection (Selected)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Low |
| Compliance | High — complies 100% with Apple Mac App Store Connect guidelines (1920x1080 16:9) |
| Flexibility | High — user can configure exact custom dimensions if needed |

**Pros:**
- Zero breaking changes to existing iPhone workflows.
- Automatically produces 1920x1080 when Mac targets are selected.

#### Option B: Separate video commands for mac vs ios
| Dimension | Assessment |
|-----------|------------|
| Complexity | Medium |
| Maintenance | Higher CLI overhead and fragmented user commands |

**Cons:**
- Fragments developer experience; unified `creative.config.json` is preferred.

## Consequences
- **Positive**:
  - Exported PNGs for iPhone, iPad, Mac, and Google Play accurately fill the physical canvas with proportional typography and device bezels.
  - Mac App Previews generated by `video_engine.py` adhere to Apple App Store Connect 1920x1080 specifications, preventing store upload rejections.
  - Video dimensions can be customized via `creative.config.json` `previewVideo.width` and `previewVideo.height`.
- **Trade-offs / Follow-up**:
  - Must ensure frontend tests and Python unit tests verify both video config resolution and export layout scaling.
